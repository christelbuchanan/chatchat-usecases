ChatChat turns an AI agent from a chat window into a trusted operating layer for work and
life. Agents can remember useful context in a **Living Brain**, work across connected
services, notice meaningful changes through **proactive workflows**, collaborate with
people in shared chats, and use a managed **Linux shell** for transparent computation.

## What you can build with ChatChat
The central pattern is a compounding loop:

1. **Capture** meetings, messages, documents, metrics, and decisions.
2. **Remember** the context that should persist across conversations.
3. **Notice** deadlines, anomalies, contradictions, and opportunities proactively.
4. **Compute** with the shell to clean data, run scripts, create charts, and verify work.
5. **Act** through the appropriate integration, with approval for consequential actions.
6. **Learn** from the decision and outcome so the next cycle is more useful.

### Everyday and team workflows

- Turn meeting notes into a living Google Doc with decisions, owners, risks, and a
  continually improving pre-read for the next meeting.
- Monitor Gmail, Calendar, Slack, HubSpot, Stripe, and other sources for material changes
  instead of producing another noisy digest.
- Add an agent's Telegram bot to a real group chat so it can answer from approved shared
  knowledge, summarize discussions, capture decisions, and coordinate follow-ups.
- Move work from Zoom or Granola notes into Jira or Google Tasks, update the project story
  in Notion or Docs, and alert the team when ownership or deadlines drift.
- Use the managed shell to reconcile exports, analyze datasets, inspect repositories, run
  tests, generate charts, and preserve repeatable scripts in the agent workspace.
- Create specialized systems for family coordination, professional impact, customer risk,
  finance reviews, content production, events, travel, health experiments, or communities.

## Design principles

### Create a portfolio of brains

Avoid one giant brain with universal access. Separate information by purpose and trust
boundary—for example Family, Personal, Work, Health, Money, People, and Play—and give each
specialist agent only the minimum context required for its role. A private control-tower
agent can receive compact summaries when coordination across domains is genuinely useful.

### Give every agent one clear job

A family coordinator, impact curator, promise keeper, health experimenter, or weekly
architect is easier to understand and supervise than an all-powerful assistant. Define
what starts the workflow, what it may read, what it may do alone, where it may speak, what
it should remember, and how success will be measured.

### Be proactive without becoming noisy

Bundle routine information into predictable briefs. Interrupt only for a material change,
deadline, safety concern, or blocked person. Distinguish “for awareness” from “you need to
decide,” respect quiet hours, and make every workflow easy to snooze, correct, or delete.

### Use integrations and the shell for different jobs

Use connected APIs as the systems of record. Use the managed shell for deterministic,
inspectable transformations: cleaning files, joining data, running code and tests,
calculating scenarios, producing charts, and validating generated artifacts.

### Keep consequential actions human-approved

Sending, publishing, paying, booking, applying, deleting, deploying, and exposing private
information require explicit approval. Keep credentials out of prompts and shell history,
distinguish evidence from interpretation, and never expose private one-to-one memories in
a shared conversation.

## Start with one four-week experiment

1. **Choose and bound:** select one play; define its brain, agent, sources, forbidden data,
   approval points, and one useful output.
2. **Run it manually:** correct assumptions and retain only preferences that should
   genuinely persist.
3. **Make one step proactive:** schedule one brief or define one material trigger, including
   quiet hours and a way to mute it.
4. **Keep, change, or delete:** retain the workflow only if the benefit exceeds its
   notification and maintenance cost.
