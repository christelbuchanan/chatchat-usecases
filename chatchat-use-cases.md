# The ChatChat use-case playbook

> Want a shorter, action-oriented starting point? Try
> [10 plays for lifemaxxing with ChatChat](chatchat-lifemaxxing-plays.md).

ChatChat is most useful when it is more than a chat window. Give an agent a durable
Living Brain, connect the services where work already happens, let proactive workflows
notice meaningful changes, and use the managed shell for the computational last mile.

The ideas below are recipes, not promises that every account has every connector or
permission. Keep consequential actions, like sending, publishing, paying, deleting, or
changing production systems behind explicit human approval.

## The compounding loop

The strongest workflows share one loop:

1. **Capture:** meetings, messages, documents, metrics, and decisions enter through an
   integration or chat.
2. **Remember:** the Living Brain connects the new information to people, projects,
   preferences, and previous decisions.
3. **Notice:** a proactive workflow watches for a deadline, anomaly, contradiction, or
   opportunity instead of waiting for a prompt.
4. **Compute:** the shell cleans files, joins datasets, runs scripts, produces charts,
   or validates an answer.
5. **Act:** the agent drafts or performs an approved action in the right tool.
6. **Learn:** the final decision and its outcome return to the Living Brain, improving
   the next cycle.

## 20 high-leverage use cases

### 1. The briefing document that gets smarter every week

After a meeting, send notes or a transcript to the agent. It reconciles names and
decisions with the Living Brain, checks Google Calendar for the next milestone, and
updates a living Google Doc with decisions, owners, risks, and unresolved questions.
Before the next meeting, a workflow produces a one-page pre-read containing what
changed—not a generic resummary of everything.

**Try:** “Turn these notes into our project brief. Preserve prior decisions, flag any
contradictions, add owners and dates, and draft the three questions we must settle next.”

### 2. An inbox chief of staff, not another email digest

Connect Gmail and Calendar. The agent groups mail by commitments and relationships,
recognizes which senders and projects matter from memory, and only interrupts when a
message changes a deadline, blocks someone, or needs a decision. It can prepare a reply
and calendar options, while leaving the actual send for approval.

**Proactive trigger:** “Alert me when an important email has no answer after one business
day, or when its promised date conflicts with my calendar.”

### 3. A Telegram teammate in a real group chat

Create a Telegram bot for an agent and add it to a project, family, community, or event
group. Mention it to retrieve shared context, summarize a noisy discussion, turn a poll
into a plan, or settle “what did we decide?” without moving everyone to another app.
The agent can ingest supported attachments and keep the group aligned without replying
to every message.

**Try:** “When mentioned, answer from the project brain. Every Friday, post decisions,
open questions, and next actions; never expose private one-to-one memories in the group.”

### 4. The founder’s morning control tower

Combine Gmail, Calendar, Slack, HubSpot, Stripe, and Plaid signals into a five-minute
brief: cash movement, customer risk, pipeline changes, team blockers, and today’s hard
trade-offs. The Living Brain supplies strategic context; proactive analysis selects only
material changes; the shell can calculate runway or scenario ranges from exported data.

### 5. Customer rescue before the cancellation

Watch support conversations, Slack, HubSpot, Stripe, and product notes for a cluster of
signals: repeated friction, a silent champion, a failed payment, or a renewal approaching
without engagement. The agent assembles an evidence-backed account brief and drafts a
personal recovery plan for the owner to approve.

### 6. A relationship radar with a memory

Use Gmail, Calendar, LinkedIn, and HubSpot to remember how you met, the last promise made,
their interests, and the right follow-up cadence. Before a meeting, receive a concise
relationship brief. Afterward, the agent captures the new commitment and proposes a
thoughtful follow-up rather than an automated “just checking in.”

### 7. The meeting-to-execution conveyor belt

Zoom or Granola notes become structured decisions; actions go to Jira or Google Tasks;
the project narrative updates in Notion or Google Docs; and Slack receives a short recap.
A workflow checks later whether the recorded owner and due date still match reality and
raises drift before the next status meeting.

### 8. A product discovery synthesis engine

Feed interview notes, forms, emails, tickets, and call transcripts into one research
brain. The shell clusters quotes and themes, but the agent preserves links back to the
original evidence. It updates a Google Sheet of requests and produces a narrative that
separates frequency, severity, willingness to pay, and strategic fit.

### 9. Release commander with rollback awareness

Connect GitHub, Jira, Slack, and Calendar. Before release, the agent builds a checklist
from the actual pull requests and tickets, uses the shell to run tests or inspect diffs,
and checks for calendar conflicts. After deployment, it watches for incident signals and
assembles a timeline. Production changes and rollbacks remain approval-gated.

### 10. The repository archaeologist

Ask a question in plain language; the agent uses the shell to search code, inspect Git
history, run targeted tests, and create a dependency map. The Living Brain remembers the
reason behind awkward architecture, not just what the code currently does, so future
contributors avoid repeating abandoned approaches.

### 11. A data analyst living inside the conversation

Drop in CSV, JSON, spreadsheet, or log files. The agent uses Python and shell tools to
clean, join, validate, analyze, and chart them, then writes an executive explanation in
Google Docs or Slides. Reusable scripts stay in the persistent workspace so next month’s
analysis follows the same definitions instead of reinventing them.

**Try:** “Reconcile these exports, show every assumption, produce a chart and an anomaly
table, and save a repeatable script for next month.”

### 12. The finance close detective

Combine Stripe, Airwallex, Plaid, Google Sheets, and invoice documents. The agent can use
the shell to normalize exports, identify duplicates and unexplained deltas, and prepare a
close packet with source links. A proactive workflow flags material exceptions; a human
approves any movement of money or accounting-system change.

### 13. A content studio with institutional taste

The Living Brain holds voice, audience, approved claims, past winners, and phrases to
avoid. Start from a meeting or launch brief; create channel-specific drafts for LinkedIn,
X, Instagram, TikTok, or YouTube; use Canva, Figma, or Higgsfield for assets; and keep
publishing behind review. Later, performance data informs the next creative brief without
reducing the brand to engagement bait.

### 14. Event producer on autopilot—until judgment is needed

Use Luma, Google Forms, Calendar, Maps, Gmail, and Telegram. The agent turns registrations
into a guest intelligence brief, spots dietary or access needs, drafts reminders, plans
routes, and gives the live team a Telegram command center. Escalations are based on real
exceptions, not a flood of routine notifications.

### 15. A travel disruption guardian

The agent remembers preferences and constraints, connects itinerary email and Calendar,
and uses Maps, Places, Uber, or Grab context to build the day. A proactive workflow notices
a late arrival or a meeting moved across town, recalculates the plan, and presents options
with trade-offs before changing a booking or spending money.

### 16. The personal health experiment lab

Bring together Oura, Whoop, Garmin, Strava, Wahoo, Rouvy, Ultrahuman, MyFitnessPal,
InBody, Clue, or Terra data. The shell can align time series and compare sleep, training,
nutrition, travel, and subjective notes; the Living Brain remembers hypotheses and
confounders. Weekly summaries should describe correlations and questions—not diagnose or
replace professional medical advice.

### 17. Household operations without the admin tax

A private Telegram group becomes the front door for receipts, voice notes, shopping
ideas, and schedule changes. The agent extracts tasks, updates shared Google Tasks and
Calendar, maintains a household reference document, and sends a Sunday preview. Private
memories stay scoped away from group-visible responses.

### 18. Community memory and newcomer concierge

In a Telegram or Slack community, the agent answers repeated questions from approved
community knowledge, points to original sources, summarizes long threads, and captures
proposals. It can welcome newcomers with a personalized orientation while escalating
moderation and sensitive people decisions to humans.

### 19. The “promise ledger” across every channel

Whenever you say “I’ll send it,” “we’ll decide Friday,” or “I owe you an intro,” the agent
records the commitment with its source. Gmail, Slack, Telegram, meetings, Tasks, and
Calendar become one ledger. A workflow nudges you before the promise expires and closes
the loop only when evidence of completion appears.

### 20. A personal operating-system review

At week’s end, the agent compares Calendar reality, completed Tasks, communication load,
health signals, and stated priorities. The shell creates trend charts; the Living Brain
recalls previous experiments; and the agent proposes one change for the next week. The
result is a small feedback loop, not a judgmental productivity score.

## Audience blueprints: divide the load, not just the to-do list

There is no single way that mothers or professional women organize their lives. The
blueprints below respond to two common realities—high context-switching and a large amount
of invisible coordination—without assuming that care work, household work, or emotional
labor should belong to women. Partners, relatives, colleagues, and co-parents can share
the same systems and should share the work.

The key design choice is to avoid one giant brain with one overworked assistant. Create
separate brains for separate trust boundaries, then give each agent a clear job. Share a
small piece of information between them only when it is needed.

### Blueprint A: a family operating system for a busy mum

#### Structure the brains

| Brain | Keep here | Keep out |
| --- | --- | --- |
| **Family hub** | Shared calendar, school dates, meal preferences, household routines, emergency contacts, packing lists | Private reflections, confidential work, children's unnecessary sensitive data |
| **Each child** | Age-appropriate routines, current activities, teacher communications, forms, medical or access instructions that are genuinely needed | Sibling information and an indiscriminate lifetime archive |
| **Personal** | Goals, energy patterns, ideas, friendships, private notes, and what restores you | Content that another household member can see |
| **Work** | Projects, decisions, stakeholders, accomplishments, and professional development | Family health, school, and private household information |

Store the minimum useful information, set a review date for sensitive details, and make
the shared-versus-private boundary explicit. A child's privacy matters even when a parent
has access to the information.

#### Give agents roles

- **Family coordinator:** reads the shared family hub, reconciles school email with the
  family calendar, maintains recurring checklists, and prepares one calm daily brief.
- **Meal and household planner:** considers preferences, schedule, leftovers, and budget;
  prepares a flexible plan and shopping list; and learns which plans actually worked.
- **School and forms concierge:** extracts dates, requirements, and action items from
  messages or attachments, but asks before submitting forms or sharing personal data.
- **Personal space agent:** protects time for health, friends, learning, and rest. It is
  deliberately private and does not turn every free hour into another chore.

#### Proactive workflows worth building

1. **The 07:00 launch brief:** today’s locations, weather-sensitive items, forms due,
   transport conflicts, and the one thing that needs attention—never the entire backlog.
2. **The school-email distiller:** turn ten newsletters into dated actions, add proposed
   calendar events, and alert only when a deadline or plan changed. The shell can extract
   tables and dates from awkward PDF newsletters before the agent checks them.
3. **The handover packet:** before a co-parent, partner, grandparent, or sitter takes over,
   create a time-bounded brief with logistics and essential instructions rather than
   granting access to the whole family brain.
4. **The Sunday load balancer:** show the coming week by owner, surface unassigned work,
   and ask the household to redistribute it; do not silently assign everything to Mum.
5. **The memory maker:** collect family photos and short Telegram notes into a monthly
   story draft, with human approval before it is shared or added to a lasting archive.

**Try:** “Every Sunday at 18:00, prepare our family week on one page. Group it by person,
place, and day; highlight clashes and unowned tasks; suggest a fair redistribution; and do
not change calendars until we approve.”

### Blueprint B: a professional operating system for women with crowded calendars

This blueprint is useful for leaders, founders, independent professionals, people
returning from leave, and anyone balancing delivery with relationship-heavy work. It is
not about asking women to optimize around unfair expectations; it is about making work,
impact, and boundaries more visible.

#### Structure the brains

| Brain | Purpose |
| --- | --- |
| **Role and strategy** | Objectives, decision principles, business context, and what you have explicitly chosen not to do |
| **Projects** | One scoped brain per major initiative, containing sources, decisions, risks, owners, and definitions of done |
| **People and relationships** | Appropriate professional context, commitments, feedback preferences, and follow-ups—not gossip or inferred sensitive traits |
| **Impact portfolio** | Wins, metrics, positive feedback, hard problems solved, lessons, and supporting evidence for reviews or a CV |
| **Growth and opportunities** | Skills to build, mentors, speaking ideas, roles, compensation research, and long-term experiments |
| **Private leadership journal** | Draft thinking, difficult trade-offs, patterns to examine, and confidential reflections with the narrowest access |

#### Give agents roles

- **Chief-of-staff agent:** turns objectives, Calendar, Gmail, and Slack into a daily
  decision brief; protects focus time; and notices when the calendar contradicts strategy.
- **Meeting advocate:** prepares evidence, desired outcomes, stakeholder context, and the
  question to ask; afterward, it captures decisions and makes ownership explicit.
- **Impact curator:** gathers measurable outcomes and attributed feedback throughout the
  year so performance reviews, promotion cases, portfolios, and CV updates do not depend
  on memory at the last minute.
- **Boundary guardian:** detects meetings without purpose, requests that silently expand,
  and commitments without trade-offs; it drafts a clear renegotiation rather than simply
  declining everything.
- **Opportunity scout:** connects emerging themes across people, projects, and goals, then
  proposes introductions, talks, articles, or roles without auto-applying or messaging.

#### Proactive workflows worth building

1. **The influence brief:** before an important meeting, summarize the decision, likely
   objections, evidence, allies, and a crisp opening—without stereotyping participants.
2. **The invisible-work ledger:** capture mentoring, hiring, onboarding, incident support,
   introductions, and culture work; quantify its impact and surface when it crowds out
   recognized goals.
3. **The leave-and-return runway:** build a living handover with decisions, owners, and
   escalation rules; while away, suppress routine updates; before return, summarize what
   changed without demanding a week of inbox archaeology.
4. **The opportunity window:** alert when a speaking deadline, warm introduction, role, or
   funding opportunity genuinely matches stated goals and evidence in the impact portfolio.
5. **The Friday evidence log:** ask for missing outcomes, update the impact portfolio, and
   produce a private three-line reflection: progress, friction, and next experiment. The
   shell can reconcile Calendar or project exports and chart how time matched stated goals.

**Try:** “Build my Friday impact note from this week’s Calendar, project updates, and
feedback. Separate outcomes from activity, cite the evidence, include invisible work, and
ask me before adding anything sensitive to my portfolio.”

### Blueprint C: one person, multiple worlds—without context leakage

For someone combining paid work, care, community, health, and personal ambitions, keep a
private **control-tower agent** above the domain agents. It may read their short status
summaries, but domain agents should not automatically read one another’s full brains.

The control tower can answer questions such as:

- “Where are work travel and family commitments colliding next month?”
- “Which obligations can be delegated, renegotiated, or dropped?”
- “Am I repeatedly sacrificing the goal I said mattered most?”
- “What information does the family coordinator need during this work trip—and nothing
  more?”

Use a **minimum-necessary handoff**: source agent, destination agent, exact fields, purpose,
and expiry time. For example, share “unavailable Tuesday 15:00–17:00” with the family agent,
not the confidential meeting title, attendees, and notes.

### A humane notification contract

Every agent serving a high-context life should follow the same contract:

- bundle routine information into a predictable brief;
- interrupt only for a deadline, safety issue, material change, or blocked person;
- distinguish “for awareness” from “you need to decide”;
- offer a recommended next step and the option to do nothing;
- respect quiet hours and protected leave;
- measure success in reduced mental load and recovered attention—not tasks generated.

## Three “super-workflows” to build first

### The decision flywheel

`Meeting notes → Living Brain → decision log in Docs/Notion → tasks in Jira/Tasks →
deadline monitor → next-meeting pre-read`

This closes the gap between discussing work and remembering why it happened.

### The signal-to-action radar

`Integration events → materiality filter → cross-source context → private alert → draft
action → human approval → outcome remembered`

Tune it to exceptions: a VIP email with no reply, a customer-risk cluster, a calendar
collision, an unusual transaction, or recovery data that argues against today’s workout.

### The group intelligence loop

`Telegram/Slack conversation → mention or scheduled synthesis → shared-memory-safe answer
→ decisions and owners → follow-up reminder → outcome posted back to the group`

This makes the agent a participant with a job, not a bot that comments on everything.

## Make the shell the agent’s workbench

The managed shell is ideal for deterministic, inspectable work that complements connected
services:

- normalize messy exports with `jq`, `csvkit`, or Python;
- search repositories and notes with `rg`;
- run tests, linters, migrations, or repeatable research scripts;
- transcribe or convert supported files with installed tools;
- calculate forecasts and generate charts;
- compare document versions and verify that generated artifacts contain expected data;
- retain useful files and scripts in the persistent workspace for the next run.

Prefer an integration API for the system of record, and use the shell for transformation,
validation, and computation. Do not put secrets into prompts or shell history, and require
approval for destructive commands.

## A practical setup canvas

For each workflow, write down:

| Question | Example answer |
| --- | --- |
| What starts it? | A new VIP email or weekday 08:00 schedule |
| What context may it read? | Gmail thread, Calendar, and project brain only |
| What counts as meaningful? | Deadline moved, explicit ask, or unresolved blocker |
| What may it do alone? | Classify, calculate, summarize, and draft |
| What needs approval? | Send email, publish, pay, delete, or deploy |
| Where should it speak? | Private chat unless the source was a shared group |
| What should it remember? | Final decision and outcome, not sensitive raw data |
| How will we know it works? | Fewer missed commitments and fewer low-value alerts |

Start with one narrow trigger and one useful output. Review false positives weekly. Add
autonomy only after the agent consistently shows its sources, respects memory boundaries,
and makes approval points obvious.
